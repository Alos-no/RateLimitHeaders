Examples

Accessing rate limit info after executing a request:

var context = ResilienceContextPool.Shared.Get();
try
{
    var response = await pipeline.ExecuteAsync(
        async (ctx) => await httpClient.GetAsync("https://api.example.com/v1/data"),
        context);

    if (context.Properties.TryGetValue(RateLimitContextProperties.RateLimitInfoKey, out RateLimitInfo info))
    {
        Console.WriteLine($"Remaining: {info.Remaining}/{info.Quota}");
    }
}
finally
{
    ResilienceContextPool.Shared.Return(context);
}

RateLimitInfoKey

The key used to store rate limit info in the Properties.

public static readonly ResiliencePropertyKey<RateLimitInfo> RateLimitInfoKey

Field Value

ResiliencePropertyKey<RateLimitInfo>

Examples

context.Properties.TryGetValue(RateLimitContextProperties.RateLimitInfoKey, out RateLimitInfo rateLimitInfo);

Remarks

After executing a request through a resilience pipeline with rate limit header parsing, you can retrieve the parsed rate limit info using this key.

RequestMessageKey

The key used to store the HTTP request message in the Properties.

public static readonly ResiliencePropertyKey<HttpRequestMessage> RequestMessageKey

Field Value

ResiliencePropertyKey<HttpRequestMessage>

Examples

var request = new HttpRequestMessage(HttpMethod.Get, "https://api.example.com/v1/users");
context.Properties.Set(RateLimitContextProperties.RequestMessageKey, request);

Remarks

When using per-endpoint rate limit tracking, set the request message in the context before executing the pipeline to enable proactive throttling based on the target endpoint. If not set, the strategy will fall back to using response.RequestMessage for tracking (which only affects post-response state updates, not proactive throttling).
